A lean, profile-driven kit that turns “I want to build X” into a repeatable loop: plan, build, verify, commit. One phase at a time, in a fresh context, with all state on disk.
№ 01

What RIFF actually is

RIFF is not a framework you adopt and then maintain forever. It is a kit: a small universal core, modular pieces you can delete, and a single profile.yaml that wires only what fits the way you work.

Most agent frameworks are a trap. You adopt 40KB agent definitions, pay a token tax on every call, and accumulate maintenance debt while Claude Code ships native features that replace half of what you installed. The 13 RIFF agents total roughly 60KB, between 1.4KB and 6KB each. Every piece is reviewable in under ten minutes. When Claude Code ships something that replaces one of your hooks or commands, you delete the piece. No framework-wide migration.

The loop, in one breath

RIFF turns intent into a repeatable cycle. Each phase runs in a fresh Claude Code context with full state written to disk, so you can stay in the loop and correct as you go, or walk away and let it run unattended. It works on any project, new or existing.

The four beats
BeatWhat happensWho runs it
PlanGoal-backward decomposition into tasks, grouped into parallel waves, one model picked per taskOpus
BuildTasks implemented one by one, atomic commits, deviations handled by the R1–R4 rulesCodex Sonnet
VerifyScope check, dead-code audit, adversarial pass, security pass, optional browser smoke testCodex Sonnet
CommitOne PR per phase, learnings harvested into project taste filesPipeline
The creator of Claude Code runs on roughly 100 lines of CLAUDE.md, a handful of terminals, plan mode, and a small set of slash commands. That is the target. — RIFF, Philosophy

Who it is for

Solo developers using Claude Code who want structure, quality, and the ability to walk away from the keyboard without the project falling apart. RIFF gives you the scaffolding to reach the minimal-setup ideal without reinventing the planner, the security reviewer, or hook discipline from scratch.

Inspect before adopting

Principle 01

Every file is meant to be edited. Agents are markdown, the file is the instruction. Commands are markdown with YAML frontmatter. Hooks are bash. No black boxes.

Delete when redundant

Principle 02

When Claude Code ships a native feature that replaces a piece, remove it. The framework is a kit, not a contract you are locked into.

Prune quarterly

Principle 03

Walk through DECAY.md and strip what is not earning its keep. Your framework stays yours, and stays small.

№ 02

Greenfield or brownfield

Every project enters RIFF through one of two doors. A blank slate gets a guided discovery. An existing codebase gets read, understood, and seeded with a roadmap of the work RIFF can already see.

The blank slate

Greenfield

/riff:start

Five gated stages of discovery that define the product before a single line is written.

  1. Problem definition — what, for whom, why now, and the scope choice
  2. System architecture — design, stack, risks. Adversarial review gate
  3. MVP scope — what ships in v1 versus later
  4. Research — competitive landscape, prior art, tooling
  5. Roadmap — ordered phases. Adversarial review gate
The existing repo

Brownfield

/riff:map

RIFF reads the code, infers the stack, and seeds a roadmap of work it can see: bugs, missing tests, security gaps, refactors.

Outputs:

  1. PROJECT.md — inferred product definition
  2. taste.md — conventions read from the code
  3. ROADMAP.yaml — a seeded, ordered backlog

Scope: scratch versus production

Set once at Stage 1 of /riff:start (or at init). Scope decides which gates run and how much discipline RIFF imposes.

Two scopes, two levels of discipline
ScopeMeaningWhat runs
Production Others will use it, it is deployed, or it touches auth, payments, or personal data. Full discipline: security review on every phase, R3 architecture gates, all hooks wired.
Scratch Personal or local script, no auth, no public exposure. Skips adversarial and security review. Only the “no hardcoded secrets” rule applies.
Promotion path

When a scratch project gets serious, say “promote to production.” RIFF runs the skipped discovery stages and flips the scope. Once the app is deployed, say “set up monitoring” to wire error tracking, uptime checks, and scheduled smoke tests.

Discovery outputs

A greenfield run leaves behind a small set of living documents: PROJECT.md, ROADMAP.yaml, STATE.md, and .planning/config.json for scope. In production scope it adds taste.md, INCIDENTS.md, and CONTEXT.md.

Fourteen slash commands cover the whole lifecycle, from first install to the daily build loop. Rare lifecycle actions live as protocol files you trigger by simply saying a phrase.

Core loop — daily

CommandWhen to run

Off-loop

CommandWhen to run

Conversational triggers — no slash command

Rare lifecycle actions are protocol files. You trigger them by saying a phrase, in plain language.

You say…RIFF does
“log incident”Append an entry to INCIDENTS.md.
“incident review”Quarterly review, runs the incident adversarial reviewer.
“promote to production”Flip scope, run skipped discovery, wire post-deploy monitoring.
“re-audit phase N”Re-run scope-check, adversarial, and security against a phase.
“deep audit” / “milestone review”The deep-auditor runs across phases at a milestone boundary.
“resync riff”Run the resync script and surface CLAUDE.md drift.
№ 04

Inside /riff:next

One invocation equals one phase equals one pull request. The pipeline runs as a sequence of inline steps and sub-agent calls. This is the heart of RIFF.

Sync & reconcile

Sync main, reconcile stale bookkeeping.

Read state & pick the phase

Read STATE.md and ROADMAP.yaml, choose the next phase, create the phase branch, ensure PROMPTS.md exists.

Confidence gate

The planner self-rates its confidence 1–10 against the acceptance criteria. Below the profile threshold (default 7), the pipeline pauses and asks you to clarify.

Plan Opus

Goal-backward plan built inline by the planner.

Plan adversarial review Codex gated

Challenge optimistic plans, missing edge cases, ambiguous task boundaries.

Pre-exec explanation Haiku

Plain-language summary for the dashboard. Fail-silent.

Execute Codex

Implement tasks one by one, atomic commits, parallelize within a wave, apply R1–R4 deviations.

Simplify Haiku gated

Structural smell pass on the diff: premature abstraction, misnaming, dead branches.

Scope check mechanical

scope-check.mjs diffs the plan against the summary. No LLM. Flags silently dropped tasks.

Fallow audit mechanical

Dead code, duplication, complexity, boundary violations on the diff. Sub-second, deterministic.

Smoke test browser

Boot the dev server, load changed routes in a headless browser. Gated.

Adversarial review Codex runs in parallel with 7

Hunts logic bugs, races, edge cases, off-by-one, bad assumptions. Different model family catches Claude’s blind spots.

Security review Sonnet runs in parallel with 6

OWASP top-10 scan. CRITICAL/HIGH findings auto-trigger the debugger.

Scratch shortcut

If scope is scratch, steps 6 and 7 are skipped entirely. Straight to PR.

PR, learn, report

Open the PR, append learnings to taste.md and expertise files, report with usage tracking.

The R1–R4 deviation rules

When the executor hits something outside the plan, it picks one of four behaviors. R1 and R2 keep things moving without bothering you. R3 and R4 protect you from drift.

R1
Minor bug

Fix it, log the deviation in SUMMARY.md.

R2
Obvious missing piece

Add it, log it in SUMMARY.md.

R3
Architecture change

Stop. Ask the human before touching it.

R4
Out of scope

Seed a new phase, do not build it now.

Auto-debug

If any step fails (executor crash, scope-check FAIL, adversarial FAIL, security BLOCKED, smoke fail), the pipeline routes to the debugger. It reads the failing artifact, opens the failing route in a browser if relevant, attaches screenshots, writes DEBUG.md, and proposes a fix. On RESOLVED, the failed step re-runs.

Hard limit

Two debug attempts per phase. After that, the pipeline pauses for you. Re-run with /riff:debug <bug> for a manual third attempt.

Waves: parallel inside a phase

The planner groups independent tasks into waves. Tasks in the same wave have no dependencies on each other and run in parallel. The planner’s real job is to detect when two tasks touch the same file and serialize them into separate waves.

wave 1:
  - task 1: add User schema to schema.ts
  - task 2: add Product schema to schema.ts   # SAME FILE — not parallel-safe
wave 2:
  - task 3: add users.test.ts                  # depends on wave 1
  - task 4: add products.test.ts               # depends on wave 1
№ 05

The band of six (and more)

Each agent lives as a single markdown file in agents/. The file is the instruction, fully editable. Thirteen specialists, plus one mechanical gate that runs with no LLM at all.

Build & review

Planner

Builds PLAN.md · default Opus

Goal-backward planning from the acceptance criteria. Decomposes into tasks, groups them into parallel waves, picks a model per task. Reads the profile and taste files.

model · Opus  |  configurable per phase

Executor

Implements tasks · default Codex

Implements the plan task by task with atomic commits, parallelizes within a wave, applies the R1–R4 deviation protocol. Falls back to Sonnet when Codex is unavailable.

runtime · Codex → Sonnet fallback

Adversarial reviewer

Hunts bugs · Codex CLI

Logic bugs, race conditions, edge cases, missing error handling, off-by-one, bad assumptions. A different model family catches Claude’s blind spots. Writes REVIEW.md.

verdict · PASS / FAIL

Security reviewer

OWASP scan · default Sonnet

Auth, input validation, injection, IDOR, secrets, error handling on every production phase. Writes SECURITY.md. CRITICAL/HIGH findings auto-trigger the debugger.

verdict · PASS / WARN / BLOCKED

Pre-artifact adversaries

Four reviewers that challenge a document before it locks in, each at a different gate.

AgentChallengesWhere
Plan-adversarialOptimistic plans, missing AC edge cases, ambiguous task boundariesnext, Step 4b
Architecture-adversarialThe system architecture, before scope and roadmap lockstart, Stage 2.5
Roadmap-adversarialOrdering, dependencies, phase granularitystart, Stage 4.5
Incident-adversarialThe synthesis draft of a quarterly incident reviewincident review

Quality & learning

Simplifier

Structural smell · Haiku

Looks for premature abstraction, misnaming, dead branches, copy-pasted code that should be a function. Budget-gated.

Debugger

Auto-triggered on FAIL · Opus

Reads the failing artifact, opens the failing route in a headless browser, screenshots it, writes DEBUG.md with root cause and fix.

Improver

Harvests learnings · Haiku

Turns recent phases into patch proposals for taste.md and stack files. Reviewed, then merged, deferred, or rejected.

Deep-auditor

Cross-phase · milestone boundary

Reads all phases in a milestone, finds systemic issues, contradictions, and decay. Triggered conversationally or at a milestone tag.

The mechanical gate

Scope check no LLM

scripts/scope-check.mjs

Diffs PLAN.md against SUMMARY.md. Flags tasks that were silently dropped and smoke commands that were never reported. Runs inline, deterministic, instant. The cheapest reviewer in the band.

№ 06

Hooks & model dispatch

Hooks are small scripts that fire on an event, like a commit. They come in three buckets, and your profile decides which ones wire. Below them, RIFF dispatches work across four model families, each with a job it is good at.

The three buckets

Bucket A

Always wired · universal discipline

destructive-guard — block rm -rf, force-push to main, hard resets.
boundary-check — block cross-boundary imports.
typecheck-gate — block commits that break tsc.
test-gate — block commits that break the suite.

Bucket B

Security-adaptable · risk-driven

route-auth-guard — protect auth-sensitive routes.
idor-detector — flag queries not scoped to the user.
input-validation-guard — flag unvalidated input.
todo-orphan-guard — block // TODO without a phase.

all-on for cautious · partial for balanced · off for fast

Bucket C

Stack / convention helpers

registry-reminder — nudge to update the registry.
migration-gate — block migration changes not yet run.
notify-human — ping you via the configured channel.

Model selection

RIFF dispatches across three Claude families plus the Codex CLI. Each family is used where it is strongest.

Four families, one job each
FamilyWhen used
OpusPlanning (default). Debug (default). Adversarial fallback when Codex is unavailable.
SonnetClaude fallback execution. Security review. Debug cost override. General-purpose work.
HaikuSimplifier. Pre-exec and post-mortem explanations for the dashboard.
CodexAdversarial review (different model family, catches Claude’s blind spots).

Codex is optional

The Codex CLI (@openai/codex) is not required. If it is missing, adversarial and plan-adversarial reviews fall back to Opus, and the fallback is announced in the pipeline output. To get the cross-family pass, install it and run codex auth once.

Reference shelf

The profile that tunes everything, the default that skips the questions, the budget chain, the unattended-run rules, and the file layout on both sides of the symlink.

The default profile

Onboarding has two paths: default (zero questions, writes a safe baseline) or custom (the full question set). The same baseline is the tier-3 fallback at the bottom of the resolution chain, shipped as templates/profile.default.yaml.

Budget resolution

A four-level fallback chain decides every model choice and whether to run optional steps. First match wins.

Per-phase override

In ROADMAP.yaml: executor_model:, simplify:, etc.

Per-project override

In ROADMAP.yaml: top-level budget_quality:.

Profile default

In profile.yaml: budget.default_quality.

Hardcoded default

Unattended runs & HITL

/riff:wave bundles parallel-eligible phases and lets Codex execute while you are away. A phase qualifies when it is todo, tagged mode: AFK, not in production provider mode, and all its dependencies are done.

AFK
Autonomous

Default. Even code-only auth and payment work qualifies; the reviewers are the safety net.

HITL
You present

Real OAuth against a prod IdP, real checkout, MFA, DNS cutover, irreversible migrations.

SANDBOX
Sandbox HITL

Provider flows in sandbox mode. Verified through the headless browser protocol instead of pausing.

The dashboard

/riff:dashboard boots a local web server (Bun, port 4000): a kanban view of all phases, plain-language explanations at your declared level, and generation metadata per phase: real duration from git timestamps, file diff stats, gate outcomes, Codex usage, and the agents seen in commit trailers. Read-only. Driving still happens in the terminal.

№ 08

What discovery leaves behind

Before a single line of code, /riff:start turns a conversation into design artifacts: user stories, ASCII wireframes for the key screens, a system diagram, and a data model. Everything below is generated, then committed to disk.

Scope caveat

The wireframes and diagrams belong to Stage 2, which is skipped entirely when scope: scratch. Personal and local scripts get user stories but no page maps, data models, or architecture diagrams. Wireframes are never skipped for web projects in production scope.

User stories

Extracted in Stage 1 as one of the nine extraction axes (“Key User Stories”). Written in the classic As-a / I-want / so-that form, each with its own acceptance criteria.

Story — Plan a phase

As a solo developer, I want to run one command that plans, builds, and reviews the next phase, so that I can stay in the loop without orchestrating each step by hand.

Acceptance · ☐ one PR per phase   ☐ confidence gate honored   ☐ review before merge

Three to eight key screens, grouped by user flow. Plain text, preserved verbatim inside the page map so they live in version control next to the code.
