# Taste Reference - TanStack Start v1

> Apply when stack includes `@tanstack/react-start@^1.x` + `@tanstack/react-router@^1.x`. Read on root-route, router-init, entry-file, or build-config work.
> API details beyond these rules: Context7 MCP `resolve-library-id("@tanstack/react-start")` then `query-docs`.

## Core Rules

1. **Entry files: `app/client.{ts,tsx}` and `app/server.{ts,tsx}`.** TanStack Start v1's plugin auto-resolves these names. Do NOT rename to `entry.client.tsx` / `entry.server.tsx` (legacy convention from other frameworks). If the names don't match, the plugin needs a manual `start.client.entry` / `start.server.entry` config override — rarely worth the maintenance cost. Stick to the convention.

2. **Commit `app/routeTree.gen.ts`.** This file is auto-generated by `@tanstack/router-plugin`. It MUST be tracked in git. NOT gitignored. Reason: fresh clones cannot `pnpm typecheck` until the file exists, and the plugin only regenerates it after `pnpm dev` (or an explicit CLI run). Gitignoring it produces silent typecheck failures on PR checks.

3. **routeTree.gen.ts churn = noise, not signal.** The plugin re-emits the file on every dev session with import-order changes. Treat reorder-only diffs as harmless — `git checkout app/routeTree.gen.ts` is safe before commit.

4. **`createServerFn({ method }).inputValidator(zodSchema).handler(({ data }) => ...)`.** NOT `.validator()` (pre-v1 API). NO `'use server'` pragma (Next.js convention, not TanStack Start).

5. **Typed search params via `validateSearch`.** On any route that reads `?token=…` or other query params:
   ```tsx
   export const Route = createFileRoute('/verify-email')({
     validateSearch: z.object({ token: z.string().min(1) }),
     component: VerifyEmailPage,
   });
   ```

6. **`createRootRouteWithContext<{ queryClient: QueryClient }>()` when using react-query.** Provides typed context to all child loaders. The non-context version (`createRootRoute`) is fine for projects without react-query.

7. **Tailwind 4 + `@tailwindcss/vite` + `@source` directive.** Tailwind 4 replaces PostCSS with the Vite plugin. Source globs live in `app/styles.css` via `@source` directives, NOT in `tailwind.config.ts` `content` arrays. Keep `tailwind.config.ts` near-empty (only present for shadcn CLI compatibility). Real configuration goes in `@theme` blocks inside the CSS:
   ```css
   @import 'tailwindcss';
   @source './**/*.{ts,tsx}';

   @theme {
     --color-primary: oklch(...);
   }
   ```

8. **husky v9 + lint-staged 15.x.** husky v9 removed `husky install`. The `prepare` script is bare `husky` (with optional preceding setup):
   ```json
   { "scripts": { "prepare": "node scripts/security/install-tools.mjs && husky" } }
   ```
   `lint-staged` 15.x auto-restages files after formatting — hook scripts don't need explicit `git add` logic. Contributors never run `husky install` manually; `pnpm install` wires the hooks via `prepare`.

## Anti-Pattern Checklist

| Found                                                  | Replace with                                                  |
| ------------------------------------------------------ | ------------------------------------------------------------- |
| `app/entry.client.tsx` / `app/entry.server.tsx`        | `app/client.tsx` / `app/server.ts` (convention)               |
| `routeTree.gen.ts` in `.gitignore`                     | Commit it; fresh clones need it for typecheck                 |
| `'use client'` pragma in routes/components             | Strip — TanStack Start ignores it (Next.js convention)        |
| `createServerFn({ ... }).validator(...)`               | `.inputValidator(...)` (v1 API)                               |
| `tailwind.config.ts` populated with `content: [...]`   | Near-empty config + `@source` in `app/styles.css`             |
| `prepare: "husky install"`                             | `prepare: "husky"` (v9 dropped the install shim)              |
| Reading search params via `window.location.search`     | `validateSearch` + `Route.useSearch()` typed read             |
| `createRootRoute()` then `useRouteContext()` for queryClient | `createRootRouteWithContext<{ queryClient: QueryClient }>()` |
