# /riff:stress

Stress the app the way a real attacker and a traffic spike would. Static analysis always runs (no app needed). Supply `--target <url>` and it adds real attacks plus a real load ramp against the running instance.

Distinct from `security-reviewer` (static, per-phase, diff-scoped). Stress is on-demand, whole-app, and active.

## What You Do

Read `protocols/STRESS.md` in full and run its flow. The protocol is the source of truth; this file is the entry point. Dispatch + effort per § Model & effort dispatch — sub-agents spawn by `subagent_type` (their `effort:` frontmatter is the lever); set `model:` on the call when a phase needs a non-default model. "think hard" keywords are no-ops on Opus 4.8 / Claude 4.x.

1. **Phase 0** — scope, resolve `--target`, run the **safety gate** (local/staging only; production refused for active testing).
2. **Phase 1** — recon: map endpoints, scale-sensitive surface, auth model, test identities → `.planning/stress/.recon.json`.
3. **Phase 2** — static pass, two parallel agents: whole-codebase `security-reviewer`, and `load-tester` in static mode.
4. **Phase 3** (only with an allowed target) — active pass: spawn `red-teamer` once per attack class in **parallel** (auth, injection, IDOR, rate-limit/DoS, config/exposure), plus `load-tester` in active mode running the load ramp.
5. **Phase 3.5** — adversarial verify: Codex (`gpt-5.5 high`) refutes each CRITICAL/HIGH finding; false positives dropped. Budget-gated (off in `frugal`, every finding in `max`).
6. **Phase 4** — synthesize one report at `.planning/stress/YYYY-MM-DD-stress.md` from `templates/STRESS.md`. Verdict + `needs_specialist` in frontmatter.
7. **Fixes** — `--seed` seeds each top fix as a phase (R4). Otherwise list them and ask.

## Safety (non-negotiable)

- Active attacks and load only against a host the user type-confirms is local or staging they own.
- A production-looking target → static only, no override.
- No data-destroying payloads without explicit reversible scope.

## Return

Terminal summary stays to: verdict, breaking point ("holds to X users, degrades at Z"), count of CRITICAL/HIGH findings, whether a specialist is needed, artifact path. Detail lives in the report.

## Anti-Patterns

- Don't run active tests against production.
- Don't report a code-read suspicion as "exploited" — active findings need a request/response proof.
- Don't call parallel agents a load test — load is generated by `autocannon`, agents divide the analysis.
- Don't auto-build fixes — seed them.
